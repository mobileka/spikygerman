01Foundations

Every swatch below is painted with the live token, and the resolved value is read back from the browser — switch the theme and the sheet re-reads itself. Six semantic roles cover the whole product: canvas, surface, tinted surface, text, secondary text, muted meta.

Dark mode is a re-derivation, not a filter. Dark values are OKLch at hue 264, and the accent brightens while its ink flips to dark. Status colours are fills only — small text reads from --success-ink, --danger-ink and their siblings so 12px labels stay legible.

Theme boot contract

data-theme on <html>, resolved before first paint

The screens read localStorage["spiky-theme"], fall back to prefers-color-scheme, and write data-theme="light|dark" in an inline script in the head — no flash, no theme-dependent JavaScript in the body.

data-theme="light" data-theme="dark" theme resolved pre-paint system preference honored

02Typography

One family, seven steps. Inter for everything from hero questions to table numerals; the mono stack only for code-like content in documentation. Russian UI copy and German lesson text live in the same column — both must wrap, never clip.

Numbers that move get tabular figures. Progress captions, stat values, prices, level chips and quiz counters all set font-variant-numeric: tabular-nums, so a value ticking from 9 to 10 does not shift the row.

03Space & shape

One spacing ladder, one radius ladder. The bars and squares below are drawn with the tokens themselves, so the levers in the tweak panel move them.

Spacing ladder

Radius ladder

04Elevation & motion

Three elevation states, two durations, one curve. Card depth is a 1px ring plus a 1px shadow, always as a pair — the ring is what keeps cards crisp in dark mode.

flat

--elev-flat · content sitting directly on the canvas

ring + raised

--elev-ring + --elev-raised · the canonical card

tinted surface

--surface-warm · the pressed/selected alternative

Motion

150ms for colour and state · 250ms for size and position · cubic-bezier(0.77, 0, 0.175, 1)

width transitions with --motion-base; press feedback is a 1px shift, never a scale
Reduced motion is a first-class state. prefers-reduced-motion: reduce collapses both durations to ~0ms and removes the press shift, while results still change in the same order.

05Device shell

The phone is presentation, not product: 390 × 844 screen, 10px bezel, 52px outer radius, 42px screen radius, 50px top safe area (status bar + dynamic island), 29px bottom for the gesture indicator. Two hardware rules — the frame never carries theme colour, and app content never enters the safe areas.

09Governance

The system only holds if new screens consume it. These are the rules that keep the next screen from inventing a tenth radius.

Do

  • Reach for a token or an existing class before writing a new value.
  • Add a new value to tokens.css and tokens.json in the same change.
  • Keep one accent action per screen.
  • Pair every colour-coded result with a sentence in Russian.
  • Compose with the od-layout primitives instead of new flex wrappers.

Don't

  • Write literal hex, px radius, ms duration or shadow values in a screen.
  • Use --muted for interactive text, or status fills as text colour.
  • Add a fourth elevation, a second accent hue or a third duration.
  • Mix 6px and 8px radii inside one card.
  • Tint the phone chrome with theme colours.
